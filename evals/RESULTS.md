# Identity resolution: evaluation results

Generated by `python evaluate.py`. Positive = the source is about the subject; negative = a namesake. *Namesake leak* = share of namesakes that pass the threshold and would enter the risk score.

Sets: dev 368 (threshold tuning, rule development), test: 382, fresh seed 101: 750, golden: 20, holdout (used): 18, holdout2: 16. The synthetic sets come from `eval_synth.py`; golden and the holdouts are hand-written (`evals/*.jsonl`). *holdout (used)* was written after v2 and its errors drove v3, so it is no longer independent; *holdout2* was written before the v3 changes and never used to change them: it is the honest number. All are fictional: they test the matcher's logic, not real-world accuracy.

Matchers: `name_only` (name similarity), `heuristic_for_only` (v2 with the evidence-against features switched off, an ablation), `heuristic` (matching.py, v3).
